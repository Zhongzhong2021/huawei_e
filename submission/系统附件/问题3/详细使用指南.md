# 详细使用指南

以下命令以已进入交付目录 `/path/to/问题三`、已按系统附件首页的环境说明安装依赖为前提。命令中的路径均按自己的机器修改；中文路径始终加引号。

## 输入文件

`run.py predict --split valid|test` 读取一个对齐 pickle 文件：顶层字典含 `train`、`valid`、`test`；每个 split 至少含等长的 `text`、`audio`、`vision`、`text_bert`、`id`、`raw_text` 数组。`text` 每条形状为 `[L,768]`，`audio` 为 `[L,74]`，`vision` 为 `[L,35]`，三者的 `L` 相同；`text_bert` 是整数 `[3,L]`，第二行是 0/1 attention mask。带标签的数据还需同一 split 中的 `regression_labels`（-3 到 3）与 `classification_labels`（0、1、2），符号必须一致。

`--split special` 读取一个目录，目录中恰有 `01.pkl` 到 `20.pkl`；每个文件是同样字段的单条字典，`id` 必须与两位文件名一致。专项推理读取题目特征。将比赛数据放在 `data/aligned_50.pkl` 与 `data/attachment4_aligned/`，或通过命令指定其绝对路径。

## 预测

```bash
cd /path/to/问题三
DATA="$PWD/data"
HF_HUB_OFFLINE=1 python run.py predict --model uncertainty --input "$DATA/attachment4_aligned" --split special --output "$PWD/output/uncertainty-special" --device cpu
HF_HUB_OFFLINE=1 python run.py predict --model selfmm --input "$DATA/attachment4_aligned" --split special --output "$PWD/output/selfmm-special" --device cpu
HF_HUB_OFFLINE=1 python run.py predict --model tetfn --input "$DATA/attachment4_aligned" --split special --output "$PWD/output/tetfn-special" --device cpu
```

有 NVIDIA GPU 时可把 `--device cpu` 改成 `--device cuda:0`。验证集和测试集预测只需更换输入与 split：

```bash
HF_HUB_OFFLINE=1 python run.py predict --model uncertainty --input "$DATA/aligned_50.pkl" --split valid --output "$PWD/output/uncertainty-valid" --device cuda:0
HF_HUB_OFFLINE=1 python run.py predict --model uncertainty --input "$DATA/aligned_50.pkl" --split test --output "$PWD/output/uncertainty-test" --device cuda:0
```

输入不在建议目录时，用绝对路径，例如 `--input "/path/to/附件4/对齐版本"`。每次调用创建指定输出目录中的 `predictions.csv`；主模型另生成 `explanations.jsonl`，一行一条 JSON。输出目录必须不存在或为空，重复运行请指定新目录；非空目录会在加载权重前拒绝。基线本身不提供可核算的原生归因，运行入口不会输出其解释文件。

CSV 字段：`id` 是原样字符串；`polarity` 为负/中/正的 `0/1/2`；`intensity` 是按最终类别约束到 [-3,3] 的强度，中性固定 0，非中性若与回归分数异号会压到绝对值 `1e-6`；`raw_intensity` 是未作类别约束的回归输出；`aux_logit_0/1/2` 是分类辅助输出。带标签输入另有 `true_intensity`、`true_class`。主模型通过 `policy.json` 中 `decision_mode=classification, neutral_bias=-0.4` 选择类别；两个基线通过回归阈值选择类别。最终类别读取`polarity`字段。

主模型解释 JSON 的 `target` 是**经过中性偏置校准后，预测类与最强竞争类的 logit margin**；`score ≈ bias + modal_scores.T + modal_scores.A + modal_scores.V`，`accounting_error` 记录数值核算误差。`single`、`pair`、`local` 记录单项、成对与位置项；每个成对交互各分一半给参与的两个模态。`modality_shares` 将三个模态的**净贡献绝对值**归一化，`principal_modality` 是最大份额模态。`source_index` 和 `top_evidence` 提供原对齐位置及分数。解释量分解当前模型的上下文化读出。`precision_weights`用于融合，`unimodal_residual_variances`表示单模态残差方差。分类贡献对应logit margin，回归贡献对应预激活`q`，两类结果按各自目标读取。

已冻结的完整验证、测试、附件4输出在 `results/uncertainty`、`results/selfmm`、`results/tetfn`；主模型全部20条可读卡片在 [附件4_全20条解释卡](results/附件4_全20条解释卡.md)，模型说明与实验分析见单独提交的论文PDF。

## 评价已有预测

已冻结指标在各模型的 `results/<模型>/metrics.json`；其中 `valid.final` 和 `test.final` 是最终类别和强度的指标。若对自己生成的有标签 CSV 计算相同指标，可从交付目录执行：

```bash
python run.py evaluate --predictions "$PWD/output/uncertainty-valid/predictions.csv" --output "$PWD/output/uncertainty-valid/metrics.json"
```

有标签的验证集用于计算预测指标；附件4的CSV记录预测与解释。

## 重新训练

重新训练需要单独准备 `bert-base-uncased` 原始权重，见`weights/<模型>/config.json`及`THIRD_PARTY_NOTICES.md`。`--pretrained` 只能指向含 `config.json` 与**单文件标准 Hugging Face** `model.safetensors` 或 `pytorch_model.bin` 的本地目录。`assets/bert-base-uncased`保存推理所需的结构配置；训练使用另行准备的完整预训练权重目录。

```bash
HF_HUB_OFFLINE=1 python run.py train --model uncertainty --aligned "$DATA/aligned_50.pkl" --pretrained "/path/to/bert-base-uncased" --output "$PWD/output/train-uncertainty-s17" --device cuda:0 --epochs 20
```

`--model` 也可选 `selfmm`、`tetfn`，每次使用新的输出目录；若目录已存在，训练会拒绝覆盖。训练读取 train/valid，种子 17、最多 20 轮、任一目标刷新即重置四轮早停计数。输出包含 `environment.json`、`history.csv`、`run_manifest.json`、`winners.json`、`stats.json`、逐轮策略和检查点，以及 `best/macro_f1`、`best/accuracy`、`best/mae` 三套独立最优产物。随包主权重来自实际运行第 5 轮；该次运行总计 9 轮。三个目标的最佳轮次与策略可能不同。

可直接用新训练出的任一最优目标做推理，无需改随包权重。例：

```bash
HF_HUB_OFFLINE=1 python run.py predict --model uncertainty --bundle "$PWD/output/train-uncertainty-s17/best/accuracy" --input "$DATA/aligned_50.pkl" --split valid --output "$PWD/output/new-accuracy-valid" --device cuda:0
```

`--bundle` 必须指向某个 `best/<目标>` 目录，包含完整检查点、配置、统计与策略，模型类型须与 `--model` 一致。推理仍使用随包 BERT 配置建立结构，再严格加载所选检查点；训练配置中保存的旧绝对预训练路径不会影响搬移后推理。

## 常见错误

- `FileNotFoundError: weights/.../best.pt`：检查 LFS 是否已 `git lfs pull`，或归档是否包含真正二进制权重。
- `prediction output must be an empty directory`：换用新的输出目录，或先处理旧输出。
- `special input must be a directory` / `valid/test input must be one aligned pickle`：核对 `--split` 与输入类型。
- 形状、标签或 `01.pkl` 至 `20.pkl` 错误：按本页输入结构检查，统一使用对齐版数据。
- `--pretrained must be a local BERT directory with config and weights`：训练还缺单文件基础 BERT 权重。
- `CUDA requested but unavailable` 或 CUDA 设备错误：改用 `--device cpu`，或检查驱动、PyTorch CUDA wheel 和设备编号。

在原记录的 GPU 环境，附件4回放记录显示类别和浮点输出一致。本机另用Python 3.10.12、PyTorch 2.6.0+cpu、Transformers 4.48.3、NumPy 2.2.6完成三个模型各20条离线重放，类别全部一致；相对冻结结果，主模型强度最大差约1.08×10⁻⁶，三模型中的强度最大差约6.37×10⁻⁵、辅助输出最大差约7.41×10⁻⁵。该检查同时改变了设备和软件版本，不将差异单独归因为CPU，也不保证跨环境逐位相同。

## 证据定位与同步画面

`results/evidence_navigation/navigation.jsonl` 将原关键项的索引、字符区间和分数与媒体候选范围关联，`alignment.json` 保存逐词决策及声学检查，`summary.json` 汇总覆盖和未确定原因。`frames/` 保存实际视频帧，解释卡直接展示这些图像。`results/media_mapping.jsonl` 中的旧MMS时间用于对照。定位工具仅生成媒体导航，训练、预测和贡献计算继续使用原输入与模型。

工具在 `tools/evidence_navigation/`。其中8个纯处理模块逐字复用问题一，来源摘要记录在 `reuse.json`；运行时无需问题一目录。固定规则与模型记录放在 `config/`、`models.json`。Whisper采用 large-v3 的固定转换版本，完整版本与文件摘要见 `results/evidence_navigation/asr/protocol.json`；MFA 3.3.9的声学、词典与G2P文件须符合 `models.json`。文本校验使用标准uncased BERT词表（仅需分词器文件），词表摘要记录在 `inputs.json`。

在问题三目录执行下列步骤。变量填写对应的本地路径；`SOURCE` 指附件四对齐版本，内含20个PKL及 `videos/`。为重放选择新的 `OUT`、`WORK`，避免混入已有中间文件。`PY` 使用包含NumPy 2、Transformers、SciPy、num2words的环境；`ASR_PY` 使用faster-whisper 1.2.1环境；MFA单独使用其3.3.9环境。FFmpeg与FFprobe须在PATH中。GPU识别使用 `int8_float16`，CPU可将 `--device cuda` 改成 `--device cpu`，计算类型随之为 `int8`。

```bash
PY=/path/to/analysis/bin/python
ASR_PY=/path/to/whisper/bin/python
SOURCE=/path/to/attachment4/对齐版本
TOKENIZER=/path/to/uncased-tokenizer
WHISPER=/path/to/faster-whisper-large-v3
MFA_PREFIX=/path/to/mfa-env
MFA_MODELS=/path/to/mfa-models
OUT="$PWD/output/evidence-navigation"
WORK="$PWD/work/evidence-navigation"
"$PY" tools/evidence_navigation/inventory.py --source "$SOURCE" --tokenizer "$TOKENIZER" --output "$OUT/inputs.json"
"$ASR_PY" tools/evidence_navigation/recognize.py --inputs "$OUT/inputs.json" --models "$WHISPER" --output "$OUT/asr" --device cuda
"$PY" tools/evidence_navigation/prepare.py --inputs "$OUT/inputs.json" --asr "$OUT/asr" --output "$OUT/local" --work "$WORK"
"$PY" tools/evidence_navigation/align.py --output "$OUT/local" --work "$WORK" --mfa-prefix "$MFA_PREFIX" --models "$MFA_MODELS"
"$PY" tools/evidence_navigation/build.py --inputs "$OUT/inputs.json" --local "$OUT/local" --output "$OUT"
```

Whisper目录需包含该固定版本的 `manifest.json` 及其中列出的模型文件，识别工具启动时逐项核对摘要。运行记录中的本机路径用于追溯；重放路径由命令参数指定。单独重建当前解释卡和论文直接执行 `python paper/build_paper.py`，它读取随附的冻结定位结果，无需再次加载语音模型。

词级候选要求唯一文字对应、足够的信息锚点和0.2秒以内的跨结果边界一致性；短语级只给整体范围。支持不足项按文字对应、锚点或声学边界原因区分。同步画面采用原视频实际帧时间，表示回看区间的场景；原音视特征的精确采样时间和画面人物的发声身份另行保留为未知。

媒体内容检查另见`results/evidence_navigation/media_consistency.json`，逐条记录两种识别文本、词序匹配覆盖和两套版本的视觉可用性。双模型词序覆盖均低于0.5时标记低内容支持，该规则仅用于提示复核，不参与预测、时间候选选择或准确率统计。可用`python tools/evidence_navigation/check_correspondence.py --audit /path/to/数据关联核查`从核查输出重建记录；论文与解释CSV同时展示媒体对应状态。未触发提示不等于已验证完整对应。
