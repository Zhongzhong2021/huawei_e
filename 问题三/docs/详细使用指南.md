# 详细使用指南

以下命令以已进入交付目录 `/path/to/问题三`、已按[环境配置](环境配置.md)安装依赖为前提。命令中的路径均按自己的机器修改；中文路径始终加引号。

## 输入文件

`run.py predict --split valid|test` 读取一个对齐 pickle 文件：顶层字典含 `train`、`valid`、`test`；每个 split 至少含等长的 `text`、`audio`、`vision`、`text_bert`、`id`、`raw_text` 数组。`text` 每条形状为 `[L,768]`，`audio` 为 `[L,74]`，`vision` 为 `[L,35]`，三者的 `L` 相同；`text_bert` 是整数 `[3,L]`，第二行是 0/1 attention mask。带标签的数据还需同一 split 中的 `regression_labels`（-3 到 3）与 `classification_labels`（0、1、2），符号必须一致。

`--split special` 读取一个目录，目录中恰有 `01.pkl` 到 `20.pkl`；每个文件是同样字段的单条字典，`id` 必须与两位文件名一致。无需标签。建议把数据放在 `data/aligned_50.pkl` 与 `data/attachment4_aligned/`；数据未随交付包提供。代码使用 `pickle.load`，只打开可信比赛文件。

## 预测

```bash
cd /path/to/问题三
DATA="$PWD/data"
HF_HUB_OFFLINE=1 python run.py predict --model uncertainty --input "$DATA/attachment4_aligned" --split special --output "$PWD/output/uncertainty-special" --device cpu
HF_HUB_OFFLINE=1 python run.py predict --model selfmm --input "$DATA/attachment4_aligned" --split special --output "$PWD/output/selfmm-special" --device cpu
HF_HUB_OFFLINE=1 python run.py predict --model tetfn --input "$DATA/attachment4_aligned" --split special --output "$PWD/output/tetfn-special" --device cpu
```

有 NVIDIA GPU 时可把 `--device cpu` 改成 `--device cuda:0`。验证集和测试集预测只需更换输入与 split：

```bash
HF_HUB_OFFLINE=1 python run.py predict --model uncertainty --input "$DATA/aligned_50.pkl" --split valid --output "$PWD/output/uncertainty-valid" --device cuda:0
HF_HUB_OFFLINE=1 python run.py predict --model uncertainty --input "$DATA/aligned_50.pkl" --split test --output "$PWD/output/uncertainty-test" --device cuda:0
```

输入不在建议目录时，用绝对路径，例如 `--input "/path/to/附件4/对齐版本"`。每次调用创建指定输出目录中的 `predictions.csv`；主模型另生成 `explanations.jsonl`，一行一条 JSON。输出目录必须不存在或为空，重复运行请指定新目录；非空目录会在加载权重前拒绝。基线本身不提供可核算的原生归因，运行入口不会输出其解释文件。

CSV 字段：`id` 是原样字符串；`polarity` 为负/中/正的 `0/1/2`；`intensity` 是按最终类别约束到 [-3,3] 的强度，中性固定 0，非中性若与回归分数异号会压到绝对值 `1e-6`；`raw_intensity` 是未作类别约束的回归输出；`aux_logit_0/1/2` 是分类辅助输出。带标签输入另有 `true_intensity`、`true_class`。主模型通过 `policy.json` 中 `decision_mode=classification, neutral_bias=-0.4` 选择类别；两个基线通过回归阈值选择类别。因此不能把 `raw_intensity` 的符号直接当最终类别。

主模型解释 JSON 的 `target` 是**经过中性偏置校准后，预测类与最强竞争类的 logit margin**；`score ≈ bias + modal_scores.T + modal_scores.A + modal_scores.V`，`accounting_error` 记录数值核算误差。`single`、`pair`、`local` 记录单项、成对与位置项；每个成对交互各分一半给参与的两个模态。`modality_shares` 将三个模态的**净贡献绝对值**归一化，`principal_modality` 是最大份额模态。`source_index` 和 `top_evidence` 提供原对齐位置及分数。这些解释是上下文化读出项的分解，并非删除某片段后的因果影响。`precision_weights` 是融合精度权重，不是贡献；`unimodal_residual_variances` 不是最终预测区间。若按回归策略解释，目标则是回归预激活 `q`，不能把 q 贡献与分类 margin 贡献混用。

已冻结的完整验证、测试、附件4输出在 `results/uncertainty`、`results/selfmm`、`results/tetfn`；主模型全部20条可读卡片在 [附件4_全20条解释卡](../results/附件4_全20条解释卡.md)，论文在 [paper/](../paper/)。

## 评价已有预测

已冻结指标在各模型的 `results/<模型>/metrics.json`；其中 `valid.final` 和 `test.final` 是最终类别和强度的指标。若对自己生成的有标签 CSV 计算相同指标，可从交付目录执行：

```bash
python run.py evaluate --predictions "$PWD/output/uncertainty-valid/predictions.csv" --output "$PWD/output/uncertainty-valid/metrics.json"
```

附件4预测若无比赛真值，CSV 不含 `true_*` 字段。随包的公开来源标签审计表可以通过显式 `--labels` 对齐 `id` 与 `sample_id`，使用其 `sentiment` 和 `class_id` 计算专项指标：

```bash
python run.py evaluate --predictions "$PWD/output/uncertainty-special/predictions.csv" --labels "$PWD/results/public_label_audit/attachment4_public_labels.csv" --output "$PWD/output/uncertainty-special/metrics.json"
```

评价仅计算 Accuracy、Macro-F1、MAE 等最终指标及 `raw_mae`，不会重新选择策略。预测 CSV 和标签表的 ID 必须精确一一对应；不能把此公开源标签审计当作未观察的盲测。

## 重新训练

重新训练需要单独准备 `bert-base-uncased` 原始权重，见[模型来源与复现实验说明](模型来源与复现实验说明.md)。`--pretrained` 只能指向含 `config.json` 与**单文件标准 Hugging Face** `model.safetensors` 或 `pytorch_model.bin` 的本地目录。不要把随包 `assets/bert-base-uncased` 当作训练预训练目录，它只有配置。

```bash
HF_HUB_OFFLINE=1 python run.py train --model uncertainty --aligned "$DATA/aligned_50.pkl" --pretrained "/path/to/bert-base-uncased" --output "$PWD/output/train-uncertainty-s17" --device cuda:0 --epochs 20
```

`--model` 也可选 `selfmm`、`tetfn`，每次使用新的输出目录；若目录已存在，训练会拒绝覆盖。训练读取 train/valid，种子 17、最多 20 轮、任一目标刷新即重置四轮早停计数。输出包含 `environment.json`、`history.csv`、`run_manifest.json`、`winners.json`、`stats.json`、逐轮策略和检查点，以及 `best/macro_f1`、`best/accuracy`、`best/mae` 三套独立最优产物。随包主权重来自实际运行第 5 轮；该次运行总计 9 轮。三个目标的最佳轮次与策略可能不同。

可直接用新训练出的任一最优目标做推理，无需改随包权重。例：

```bash
HF_HUB_OFFLINE=1 python run.py predict --model uncertainty --bundle "$PWD/output/train-uncertainty-s17/best/accuracy" --input "$DATA/aligned_50.pkl" --split valid --output "$PWD/output/new-accuracy-valid" --device cuda:0
```

`--bundle` 必须指向某个 `best/<目标>` 目录，包含完整检查点、配置、统计与策略，模型类型须与 `--model` 一致。推理仍使用随包 BERT 配置建立结构，再严格加载所选检查点；训练配置中保存的旧绝对预训练路径不会影响搬移后推理。

## 常见错误

- `FileNotFoundError: weights/.../best.pt`：检查 LFS 是否已 `git lfs pull`，或归档是否包含真正二进制权重。
- `prediction output must be an empty directory`：换用新的输出目录，或先处理旧输出。
- `special input must be a directory` / `valid/test input must be one aligned pickle`：核对 `--split` 与输入类型。
- 形状、标签或 `01.pkl` 至 `20.pkl` 错误：按本页输入结构检查，不要混用未对齐数据。
- `--pretrained must be a local BERT directory with config and weights`：训练还缺单文件基础 BERT 权重。
- `CUDA requested but unavailable` 或 CUDA 设备错误：改用 `--device cpu`，或检查驱动、PyTorch CUDA wheel 和设备编号。

在验证过的 GPU 环境，交付包对20条附件4逐项回放的类别和浮点输出完全一致。CPU 与 GPU 的类别一致，浮点舍入可能相差至约 `3e-6`（包括辅助输出）；跨设备比较请采用相应容差。
